# ATS Compliance Rules

Use this reference for every CV or resume output unless the user explicitly asks for a non-ATS portfolio/profile version.

## Default Rule

Always create an ATS-safe master CV first. Any designed, graphical, PPTX, portfolio, or highly styled version should be derived from the ATS-safe master, not replace it.

## ATS-Safe Structure

Use standard, predictable section headings:

- Contact
- Professional Summary
- Skills
- Work Experience
- Education
- Certifications
- Projects
- Languages

Acceptable variants:

- Professional Experience instead of Work Experience
- Technical Skills instead of Skills
- Selected Projects instead of Projects

Avoid clever section names such as:

- My Journey
- What I Do
- Where I Have Been
- Toolbox
- Superpowers

## Layout Rules

ATS-first DOCX templates should use:

- One column.
- No text boxes.
- No sidebars.
- No images for essential content.
- No icons for essential labels.
- No tables for core resume content.
- No headers or footers for contact information.
- No skill bars, star ratings, progress bars, or infographic scales.
- No charts, decorative shapes, or floating objects.
- Normal paragraph flow from top to bottom.

Small visual touches are allowed when they do not break text extraction:

- Accent color on the candidate name.
- Accent color on section headings.
- Thin horizontal line under the name or section headings.
- Conservative typography.
- Subtle spacing and bold/italic hierarchy.

## File Rules

- DOCX is the preferred editable ATS format.
- PDF can be exported from the DOCX when the application allows PDF uploads.
- Keep a plain-text extraction check for final validation.
- Do not rely on PPTX for ATS submission.
- ODT can be useful for open-document workflows, but DOCX is usually safer for ATS portals.

## Typography

Use common fonts:

- Aptos
- Calibri
- Arial
- Cambria
- Georgia
- Times New Roman

Body text:

- 10-11 pt for most CVs.
- 9.5 pt minimum only when necessary.

Candidate name:

- 16-22 pt.

Section headings:

- 11-13 pt, bold, all caps or title case.

## Content Rules

- Spell out acronyms at least once when useful.
- Match important job-description keywords naturally.
- Use exact tool and technology names.
- Put skills in text form, not only graphical form.
- Prefer measurable achievements over responsibility lists.
- Use reverse chronological work experience unless a functional format is explicitly needed.
- Keep dates consistent, for example `Mar 2022 - Present`.

## ATS Validation Checklist

Before delivery:

- Extract text from the generated DOCX and confirm the reading order is correct.
- Confirm name, email, phone, and LinkedIn are in the body, not a header/footer.
- Confirm section headings are conventional.
- Confirm all skills are plain text.
- Confirm no essential content is inside images, charts, icons, shapes, or text boxes.
- Confirm bullets are real text paragraphs.
- Confirm there are no empty placeholder tokens.
- Confirm job-description keywords are represented truthfully when a target job is provided.

## Human-Review Variant

If a more designed CV is useful, create it as a second file:

- `candidate_cv_ats.docx`
- `candidate_cv_designed.docx`
- `candidate_cv_profile.pptx`

The ATS version remains the source of truth.
